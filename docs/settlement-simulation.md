# 공동 생존 시뮬레이션

`settings.js`의 `settlement_simulation: true`일 때 기본 생활 목표를 로컬 공동 생활기가 실행한다. 매 작업마다 LLM을 호출하지 않는다. 사용자 대화와 별도 목표는 기존 AI 명령 경로를 사용한다.

## 공통 능력과 사용자 역할 지정

이름별 고정 직업은 없다. 모든 캐릭터가 기본적으로 `generalist`(자유 생활)이며 같은 능력과 행동 규칙을 사용한다. 주변 필요와 보유 재료에 따라 채집·제작·농사를 모두 선택한다.

사용자가 역할을 지정하면 해당 작업을 우선한다. “너는 농사 맡아” 같은 요청을 받은 캐릭터가 `!setRole("farmer")`를 사용하여 저장한다. “역할 풀어”는 `!setRole("generalist")`다. AI의 자기 지시나 다른 봇의 대화로 역할을 지정하는 것은 차단한다.

- `generalist`: 주변 필요에 따라 모든 작업을 선택한다.
- `gatherer`: 돌 도구를 준비하고, 주변 원목 32개와 조약돌 32개 비축을 우선한다.
- `crafter`: 돌 도구를 준비하고 거점 근처 작업대와 화로 마련을 우선한다.
- `farmer`: 돌괭이와 곡괭이를 준비하고, 성숙한 작물을 수확하고 씨앗을 심는다. 씨앗이 없으면 근처 풀에서 확보를 시도한다. 재료가 있으면 빵을 만들고, 식량이 없고 소가 인식되면 익힌 소고기 확보를 시도한다.
- 할 일이 없거나 현재 작업이 막히면 거점 주위 약 16블록 지점을 번갈아 정찰한다.

각 봇은 체력·허기를 먼저 확인한다. 먹을 것이 있으면 먹고, 위험한 상태면 거점에서 쉰다. 밤에는 주변 침대에서 자거나 거점으로 돌아가 쉰다. 거점에서 48블록 넘게 떨어진 경우 귀환을 우선한다. 이 범위는 작업 선택 시 적용되며 이동 중의 강제 경계가 아니다. 긴급 방어·위험 회피는 기존 모드가 담당한다.

## 협력과 실제 완료 판정

봇은 재고를 약 3초마다 공유한다. 도구 제작 등에 필요한 조약돌이나 참나무 원목이 부족하고 친구에게 여유 재고가 있으면 공유 작업판에 요청을 남긴다. 약 20초 동안 전달을 기다리고, 이후에는 자체 확보를 재개할 수 있다. 친구는 자신의 최소 여유분을 남기고 직접 이동하여 아이템을 던져 전달한다.

전달은 보내는 봇의 재고 감소와 받는 봇의 최신 재고 증가가 모두 확인되어야 완료로 기록한다. 떨어뜨렸지만 줍지 못한 물건은 전달 완료가 아니다. 시설은 실제 블록 설치를 확인한다. 채집·제작은 기존 아이템 플래너의 재고 판정을 사용한다.

공동 작업에는 소유자와 만료 시간이 있는 점유 기록을 사용한다. 실패한 작업은 해당 봇에 대해 2분간 피하고, 완료·실패 이력은 최근 40개를 보관한다. 대사는 30초에 한 번 이하로 제한한다. 이는 미리 정한 역할과 규칙에 따른 시뮬레이션이며, 자유로운 건축 설계나 새로운 직업을 스스로 만들어내는 기능까지 포함하지 않는다.

## 우선순위와 저장

사용자 입력은 자율 작업 점유를 해제하고 진행 중인 자율 행동을 중단하도록 요청한다. 별도로 맡긴 아이템 목표는 자율 목표와 구분하여 유지한다. `!stop`과 대기 명령은 기존 정지·대기 동작을 따른다. 대기 중인 봇에게는 새 자율 작업을 배정하지 않는다.

상태는 `bots/shared/settlements/<서버·포트·차원·월드 ID 해시>/settlement.json`에 UTF-8 JSON으로 저장한다. 첫 관측 위치를 거점으로 삼는다. 첫 실행에서는 원하는 거점 근처에서 봇을 접속시키는 것이 좋다. 같은 서버 주소와 포트에서 다른 세이브로 바꾸면 `settlement_world_id`도 바꿔야 이전 거점과 섞이지 않는다.

`settlement_roles`는 기본적으로 빈 설정이다. 채팅에서 지정한 역할은 공유 상태의 `assignments`에 저장되어 재시작 후에도 유지되며 설정의 초기값보다 우선한다. `settlement_simulation: false`로 끄면 기존 기본 자율 루프로 돌아간다. 예전 기본 생활 프롬프트는 처음 시작할 때 새 기본 목표로 이관하며, 사용자 지정 목표와 현재 기본 목표의 대기 상태는 유지한다.

검증: `node --test tests/*.test.js`. 테스트는 게임 I/O를 대체하여 역할 선택·요청·실패 회피·전달 판정·저장을 검증한다. 실제 지형의 길찾기, 농사 및 서버 내 아이템 전달은 별도 게임 실행 검증이 필요하다.
