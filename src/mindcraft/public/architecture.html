🌸 Mindcraft System Architecture

How the pieces fit together — from your browser down into Minecraft.

Browser (you)

🖥️ Web UI

public/index.html — create agents, chat, watch inventory & bot view. Talks over Socket.IO.

⬇Socket.IO + REST (port 8080)
Main Node.js process — main.js

🧠 MindServer

mindserver.js — Express + Socket.IO hub. Routes messages between UI and agent processes, persists settings to bots/<name>/ui-settings.json.

🎮 Agent Manager

mindcraft.js — spawns one child process per agent, assigns viewer ports 3000+, restarts crashed agents.

📡 Server Probe

mcserver.js — detects Minecraft server host/port/version before connecting.

⬇child_process.spawn (one per agent)
Agent child process — init_agent.js → agent.js

💬 Conversation

conversation.js + models/ — LLM loop (OpenAI, Gemini, Claude, CLI providers…). Sends chat & tool calls.

⚙️ Actions

action_manager.js, commands/ — executes LLM requests: move, craft, build, fight.

🧩 NPC / Hybrid

npc/hybrid_controller.js, settlement & item-goal runtimes — local autonomy without waiting on the LLM.

🗂️ Memory

memory_bank.js, history.js, self_prompter.js — long-term memory & prompts.

⬇Mineflayer (Minecraft protocol)
Game & side services

⛏️ Minecraft Server

Java Edition world (LAN or online). The bot joins as a normal player.

📷 Bot View

Head-mounted camera served on ports 3000+, embedded in the UI when render_bot_view is on.

🔊 TTS

speak.js → GPT/Gemini voices or local Python server (tts/supertonic_server.py) when speak is enabled.

Message flow (one chat message)

  1. You type in the UI → Socket.IO send-message to MindServer.
  2. MindServer forwards it to that agent's child process socket.
  3. conversation.js feeds it to the LLM with memory & context.
  4. The LLM replies in chat and/or requests actions via action_manager.js.
  5. Mineflayer executes them in-game; state updates stream back to the UI every second (state-update).
